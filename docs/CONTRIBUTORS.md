# Contributors Guide & Hall of Fame

Thank you for your interest in contributing to the **BookMyShow Frontend** project! This document outlines how you can contribute, our development etiquette, and recognizes the individuals who have helped improve the application.

---

## 1. How to Contribute

We welcome contributions of all kinds, including:

- **Reporting Bugs**: Identifying reproducible bugs or broken UI interactions via GitHub Issues.
- **Suggesting Enhancements**: Proposing new features, accessibility improvements, or performance optimizations.
- **Improving Documentation**: Fixing typos, clarifying guides, or contributing code examples in `docs/`.
- **Submitting Code**: Implementing feature requests, bug fixes, or refactoring existing modules.

---

## 2. Contribution Lifecycle

1. **Find or Open an Issue**: Check existing issues before opening a new one to avoid duplicate discussions.
2. **Fork and Branch**:
    - Create a feature branch off `main`:
        ```bash
        git checkout -b feature/your-feature-name
        ```
3. **Follow Coding Standards**:
    - Write clean, strongly typed TypeScript code following [`CODING-STANDARDS.md`](./CODING-STANDARDS.md).
    - Ensure your code adheres to ESLint, Prettier, and accessibility rules.
4. **Run Quality Verification**:
    ```bash
    npm run prettier
    npm run lint
    npm run ts:check
    npm run build
    ```
5. **Submit a Pull Request**:
    - Provide a clear summary of your changes.
    - Reference any relevant issue tickets (e.g., `Closes #12`).
    - Fill out all required fields in the [Pull Request Template](../.github/pull_request_template.md).

---

## 3. Code of Conduct Highlights

- **Respectful Collaboration**: Treat all maintainers, contributors, and users with professional respect and kindness.
- **Constructive Feedback**: Offer actionable and considerate feedback during code reviews.
- **Inclusivity**: Ensure that all user interfaces and contributions respect accessibility and cultural diversity.
